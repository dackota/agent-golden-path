# Observability and evals for the agent golden path

Date: 2026-09-10

## Summary

Every layer of this stack can already emit OpenTelemetry. kagent 0.10 has Helm keys for traces and for a prompt audit log ([kagent values](https://github.com/kagent-dev/kagent/blob/v0.10.0/helm/kagent/values.yaml)). agentgateway 1.5 has an `AgentgatewayPolicy` for traces and OTLP access logs, and a Prometheus endpoint on port 15020 ([agentgateway traces](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/traces/setup.md), [metrics](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/metrics/dataplane.md)). LiteLLM has an `otel` callback, a `prometheus` callback, spend logs per key, and a `x-litellm-call-id` header to join the two ([LiteLLM OTel](https://docs.litellm.ai/docs/observability/opentelemetry_integration), [spend](https://docs.litellm.ai/docs/proxy/cost_tracking)). The chart already points container agents at `otel-collector.platform-observability.svc.cluster.local:4318` and the NetworkPolicy allows it ([_helpers.tpl](../../charts/agent/templates/_helpers.tpl), [networkpolicy.yaml](../../charts/agent/templates/container/networkpolicy.yaml)). The one missing piece is something that listens. Recommendation: on kind, run one `grafana/otel-lgtm` pod under the Service name the chart expects, turn on the three producers, and add a 40-line OTLP/JSON emitter to the stdlib agents. On a real cluster, replace the pod with the OpenTelemetry Collector Helm chart and forward to the org's Grafana stack or to Langfuse. For evals, add an `evals/` directory with promptfoo, run deterministic assertions on every PR, run LLM-graded and red-team suites nightly in-cluster through the gateway. Part 3 has the file-level plan.

## Part 1: observability

### 1. kagent 0.10

Helm keys. The chart has `otel.tracing.enabled` (default `false`), `otel.tracing.exporter.otlp.endpoint`, `.protocol` (default `grpc`), `.timeout` (15000 ms), `.insecure` (`true`), and a parallel `otel.logging.*` block with `enabled`, `endpoint`, `timeout`, `insecure` ([values.yaml v0.10.0](https://github.com/kagent-dev/kagent/blob/v0.10.0/helm/kagent/values.yaml)). The tracing guide sets `otel.tracing.exporter.otlp.endpoint: http://jaeger.jaeger.svc.cluster.local:4317` and tells you to filter on the span `agent_run [k8s-agent]` in Jaeger ([kagent tracing](https://kagent.dev/docs/kagent/observability/tracing/)).

How the values reach agents. The controller copies every `OTEL_*` variable from its own process into each agent pod (`collectOtelEnvFromProcess` in [adk_api_translator.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/core/internal/controller/translator/agent/adk_api_translator.go)). The agent runtime reads `OTEL_TRACING_ENABLED`, `OTEL_LOGGING_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` ([env/otel.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/core/pkg/env/otel.go), [telemetry/tracing.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/adk/pkg/telemetry/tracing.go)).

Spans and attributes. The A2A server middleware opens an `invoke_agent` SERVER span with `gen_ai.operation.name=invoke_agent`, `gen_ai.provider.name` (mapped from the ModelConfig provider, `kagent` for BYO agents), `gen_ai.agent.name`, and `gen_ai.agent.id`, using semconv v1.39.0 ([trace.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/core/internal/a2a/trace.go)). Google ADK, which the Go and Python runtimes wrap, emits `invoke_agent {agent.name}`, `execute_tool {tool.name}`, and `generate_content {model.name}` spans with `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.tool.name`, `gen_ai.tool.call.id`, and `gen_ai.conversation.id` ([ADK traces](https://github.com/google/adk-docs/blob/main/docs/observability/traces.md)). kagent stamps the full request and response as `gcp.vertex.agent.llm_request` and `gcp.vertex.agent.llm_response` on the `generate_content` span, capped at 32 KiB, gated by `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` ([attributes.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/adk/pkg/telemetry/attributes.go)). The Python runtime instruments FastAPI, httpx, and the OpenAI, Anthropic, and Google GenAI SDKs with OpenTelemetry SDK 1.38 and OpenLLMetry instrumentors 0.52 ([_utils.py](https://github.com/kagent-dev/kagent/blob/v0.10.0/python/packages/kagent-core/src/kagent/core/tracing/_utils.py), [pyproject.toml](https://github.com/kagent-dev/kagent/blob/v0.10.0/python/packages/kagent-core/pyproject.toml)).

Audit prompts. The audit feature is the `otel.logging` block. It sends inputs, agent replies, and messages exchanged with the LLM provider as OTLP logs to a collector, then to Loki, Datadog, Splunk, or any OTLP backend. The docs say logging works only with OpenAI and Anthropic providers ([kagent audit prompts](https://kagent.dev/docs/kagent/observability/audit-prompts/)). Our kagent default provider is Ollama ([platform/kagent/values.yaml](../../platform/kagent/values.yaml)), so prompt audit for `faq-helper`, `concierge`, and `orders-agent` is unverified until we test it or point kagent at LiteLLM as an OpenAI provider.

Metrics. `controller.metrics.enabled` (default `false`) exposes controller-runtime metrics on `:8443` with `secureServing: true` and a Service on port 8443 ([values.yaml](https://github.com/kagent-dev/kagent/blob/v0.10.0/helm/kagent/values.yaml), [controller-metrics-service.yaml](https://github.com/kagent-dev/kagent/blob/v0.10.0/helm/kagent/templates/controller-metrics-service.yaml)). I found no doc for per-agent Prometheus metrics; the docs URL `observability/metrics` returns 404. Unverified.

### 2. agentgateway 1.5

Kubernetes mode. Tracing and access-log export are both fields on `AgentgatewayPolicy` (`agentgateway.dev/v1alpha1`) targeting a Gateway. `spec.frontend.tracing` has `backendRef` (name, namespace, port), `protocol: GRPC`, `randomSampling`, `clientSampling`, `filter` (CEL), `attributes.add` and `attributes.remove`, and `resources` ([traces setup](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/traces/setup.md), [OTel config](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/traces/configs/otel.md)). `spec.frontend.accessLog.otlp` has the same `backendRef`, `protocol`, and `attributes` shape ([access log export](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/access-logs/export.md)). Both field groups exist in the v1.5.0 CRD ([agentgatewaypolicies CRD at v1.5.0](https://github.com/agentgateway/agentgateway/blob/v1.5.0/controller/install/helm/agentgateway-crds/templates/agentgateway.dev_agentgatewaypolicies.yaml)). The docs site only serves a `latest` copy; the `1.5.x` path returned 404, so field semantics are checked against the CRD, not a version-pinned page.

Standalone mode, for reference. `config.tracing.otlpEndpoint`, `otlpProtocol: http`, `headers`, `randomSampling`, and `fields.add` with CEL such as `gen_ai.prompt: 'flattenRecursive(llm.prompt)'` ([otel.yaml](https://github.com/agentgateway/agentgateway/blob/v1.5.0/examples/llm-telemetry/tracing/otel.yaml), [langfuse.yaml](https://github.com/agentgateway/agentgateway/blob/v1.5.0/examples/llm-telemetry/tracing/langfuse.yaml)). `AgentgatewayParameters` carries `env`, `image`, `logging`, `resources`, workload overlays, and `rawConfig`, and a Gateway references it through `spec.infrastructure.parametersRef` ([customize options](https://agentgateway.dev/docs/kubernetes/latest/documentation/setup/customize/options.md)).

Span attributes. Default: `gateway`, `listener`, `route`, `endpoint`, `protocol`, `http.method`, `http.host`, `http.path`, `http.status`, `src.addr`, `duration`. MCP traffic adds `mcp.method.name` (for example `tools/call`), `mcp.target`, `mcp.session.id`, `gen_ai.tool.name`, `mcp.resource.uri`, `mcp.error.code`. LLM traffic adds `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` ([attribute reference](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/traces/attribute-reference.md)). In this repo LLM calls go to LiteLLM, not through agentgateway, so the MCP fields are the ones we get.

Access logs. Same default fields as spans. Add fields with CEL, for example `attributes.add: [{name: user_id, expression: 'request.headers["x-user-id"]'}]`. The MCP variable group exposes tool, prompt, resource name, and target ([access logs view](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/access-logs/view.md)).

Metrics. Prometheus endpoint on port `15020`, path `/metrics`. Names: `agentgateway_requests_total`, `agentgateway_request_duration_seconds`, `agentgateway_response_bytes_total`, `agentgateway_mcp_requests_total`, `agentgateway_gen_ai_client_token_usage` ([data plane metrics](https://agentgateway.dev/docs/kubernetes/latest/documentation/observability/metrics/dataplane.md)).

Langfuse. Langfuse accepts OTLP at `/api/public/otel` over HTTP/JSON or HTTP/protobuf, not gRPC, with Basic auth built from the public and secret key ([Langfuse OTLP](https://langfuse.com/docs/opentelemetry/get-started)). The agentgateway Langfuse page points `otlpEndpoint` at that path and sets the auth header ([agentgateway Langfuse](https://agentgateway.dev/docs/standalone/main/integrations/llm-observability/langfuse/)).

### 3. LiteLLM 1.90

Spend tracking. `/spend/logs` returns individual transactions with `summarize=false`, or one by `request_id`, or filtered by `api_key`. Each row carries `user_api_key_user_id`, `user_api_key_team_id`, `request_tags`, and `metadata`. `/key/info` returns the key's `spend`. `store_prompts_in_spend_logs` keeps request and response text; `disable_spend_logs` turns logging off ([cost tracking](https://docs.litellm.ai/docs/proxy/cost_tracking), [virtual keys](https://docs.litellm.ai/docs/proxy/virtual_keys)). Enterprise: `/global/spend/report` ("Generate Spend Reports") and `spend_logs_metadata` custom fields are marked Enterprise ([cost tracking](https://docs.litellm.ai/docs/proxy/cost_tracking), [enterprise](https://docs.litellm.ai/docs/enterprise)).

Response headers. `x-litellm-call-id`, `x-litellm-response-cost` (plus input, output, cache-read, cache-creation, reasoning, tool-usage parts), `x-litellm-key-spend`, `x-litellm-model-id`, `x-litellm-response-duration-ms` ([response headers](https://docs.litellm.ai/docs/proxy/response_headers)).

Prometheus. `litellm_settings.callbacks: ["prometheus"]`. `/metrics` requires a bearer token since v1.85.0. Metrics: `litellm_spend_metric`, `litellm_total_tokens_metric`, `litellm_input_tokens_metric`, `litellm_output_tokens_metric`, `litellm_remaining_api_key_budget_metric`, `litellm_remaining_team_budget_metric`. Labels: `team`, `team_alias`, `hashed_api_key`, `api_key_alias`, `user`, `user_email`, `end_user`, `model`, `requested_model`, `model_id`, `api_provider`. `custom_prometheus_metadata_labels` turns request `metadata.foo` into label `metadata_foo` ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)). The Enterprise page lists Prometheus metrics under OSS, the docs page marks only managed-batch metrics "Enterprise only", and `prometheus.py` on `main` has no license check ([enterprise](https://docs.litellm.ai/docs/enterprise), [prometheus.py](https://github.com/BerriAI/litellm/blob/main/litellm/integrations/prometheus.py)). I could not fetch the file at the `v1.90.2` tag; treat "free in 1.90.2" as likely, not verified.

OTel callback. `litellm_settings.callbacks: ["otel"]` with `OTEL_EXPORTER` (`otlp_http` or `otlp_grpc`), `OTEL_ENDPOINT`, `OTEL_HEADERS`, or the standard `OTEL_EXPORTER_OTLP_*` variables. Root span `Received Proxy Server Request` with `gen_ai.*` attributes on it by default since v1.81. `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` switches to GenAI span names `{operation} {model}` and CLIENT kind. Inbound `traceparent` is honored, so an agent's trace continues into the proxy. `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=NO_CONTENT` suppresses content; `turn_off_message_logging` is the global kill switch and is already set in [gateway.yaml](../../platform/gateway/gateway.yaml) ([LiteLLM OTel](https://docs.litellm.ai/docs/observability/opentelemetry_integration)).

Langfuse callback. `success_callback: ["langfuse"]`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST`; request `metadata.trace_id`, `generation_name`, `tags` ([logging](https://docs.litellm.ai/docs/proxy/logging)).

Budget alerts. `soft_budget` on `/key/generate` sends an alert when a key nears its budget; `general_settings.alerting: ["slack"]` with `SLACK_WEBHOOK_URL`; `budget_alerts` and `spend_reports` are on by default ([alerting](https://docs.litellm.ai/docs/proxy/alerting)). "Soft Budget Email Alerts" and "Tag-based Budgets" are Enterprise ([enterprise](https://docs.litellm.ai/docs/enterprise)).

### 4. OpenTelemetry GenAI conventions and the stdlib agents

Status is Development. Required: `gen_ai.operation.name`, `gen_ai.provider.name`. Conditionally required: `gen_ai.request.model`, `error.type`. Recommended: `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.id`, `gen_ai.response.finish_reasons`. Span name `{gen_ai.operation.name} {gen_ai.request.model}`, kind CLIENT. `gen_ai.input.messages` and `gen_ai.output.messages` are opt-in because they hold PII ([gen-ai-spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)). Metrics: `gen_ai.client.token.usage`, histogram, unit `{token}`, required attributes `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.token.type`; `gen_ai.client.operation.duration`, histogram, unit `s` ([gen-ai-metrics](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-metrics.md)). The content switch `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` takes `span_only`, `event_only`, `span_and_event`, or legacy `true` ([openai-v2 instrumentation](https://pypi.org/project/opentelemetry-instrumentation-openai-v2/)).

Stdlib path. OTLP/HTTP accepts JSON at `/v1/traces` with `Content-Type: application/json`. Rules: `traceId` and `spanId` are hex strings, enums are integers, 64-bit integers are decimal strings, keys are lowerCamelCase ([OTLP spec](https://opentelemetry.io/docs/specs/otlp/)). One `urllib` POST per agent turn with a `resourceSpans` body is enough for a `invoke_agent` span, a `chat` span per LLM call, and an `execute_tool` span per MCP call. Generate a W3C `traceparent` with `secrets.token_hex` and send it to LiteLLM and agentgateway so both join the trace.

SDK path. `opentelemetry-sdk` 1.44.0 and `opentelemetry-exporter-otlp-proto-http` 1.44.0 need Python 3.10 or newer ([sdk](https://pypi.org/project/opentelemetry-sdk/), [exporter](https://pypi.org/project/opentelemetry-exporter-otlp-proto-http/)). Neither auto-instrumentation fits: `opentelemetry-instrumentation-openai-v2` traces "the OpenAI Python API library" ([PyPI](https://pypi.org/project/opentelemetry-instrumentation-openai-v2/)), and kagent's OpenLLMetry instrumentor also wraps the `openai` SDK ([_utils.py](https://github.com/kagent-dev/kagent/blob/v0.10.0/python/packages/kagent-core/src/kagent/core/tracing/_utils.py)). Our agents call `urllib` directly ([template/app.py](../../template/app.py)), so manual spans are needed either way. The SDK gives batching and retries; the JSON path keeps the image stdlib-only.

### 5. Collector and backend

Collector. `helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts`; `mode` is required (`deployment`, `daemonset`, or `statefulset`); image `ghcr.io/open-telemetry/opentelemetry-collector-releases/opentelemetry-collector-k8s`. Defaults: OTLP receiver gRPC on `4317` and HTTP on `4318`, exporter `debug`. Helm does not merge lists, so a custom pipeline must restate every item ([chart README](https://github.com/open-telemetry/opentelemetry-helm-charts/blob/main/charts/opentelemetry-collector/README.md), [values.yaml](https://github.com/open-telemetry/opentelemetry-helm-charts/blob/main/charts/opentelemetry-collector/values.yaml)).

| Langfuse v3 | Web and worker plus Postgres, ClickHouse, Redis, S3; Helm chart needs ClickHouse operator and cert-manager, Helm 3.17, Kubernetes 1.28; production guide sizes ClickHouse at 8 Gi | Six services | [self-hosting](https://langfuse.com/self-hosting), [langfuse-k8s](https://github.com/langfuse/langfuse-k8s/blob/main/README.md) |

Recommendation for kind: `grafana/otel-lgtm`. It is the only single-pod option that stores traces, metrics, and logs, so it receives kagent traces, kagent audit logs, agentgateway spans and logs, and LiteLLM spans and Prometheus metrics with one Service. Phoenix is the alternative if the team wants LLM-shaped views and evals before Langfuse. Recommendation for a real cluster: the Collector chart forwarding to the org's Grafana stack for operations, plus Langfuse (Helm) if the team wants datasets, scores, and LLM-as-judge on production traces.

### 6. Cost attribution

Where metadata lands. LiteLLM Prometheus metrics carry `team`, `team_alias`, `api_key_alias`, and `hashed_api_key` natively ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)). The minter already sets `metadata: {team, owner, agent}` and `max_budget` ([minter.py](../../platform/minter/minter.py)). Setting `key_alias: <team>-<agent>` and `team_id: <team>` on `/key/generate` puts both into every spend metric with no extra config. Whether key-level `metadata` flows into `custom_prometheus_metadata_labels` is unverified; the docs example passes metadata per request. Spend logs carry `user_api_key_team_id` and `request_tags`; tags come from key `metadata.tags` or request `tags` ([request tags](https://docs.litellm.ai/docs/proxy/request_tags)). Custom `spend_logs_metadata` needs Enterprise ([cost tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)).

Joining cost to traces. Three keys: the `x-litellm-call-id` response header equals `request_id` in `/spend/logs?request_id=` ([response headers](https://docs.litellm.ai/docs/proxy/response_headers), [cost tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)); an inbound `traceparent` makes LiteLLM's span a child of the agent's span ([LiteLLM OTel](https://docs.litellm.ai/docs/observability/opentelemetry_integration)); request `metadata.trace_id` sets the Langfuse trace when the Langfuse callback is on ([logging](https://docs.litellm.ai/docs/proxy/logging)). The agent should record `x-litellm-call-id` and `x-litellm-response-cost` as span attributes so cost is visible in the trace without a database join.

### 7. A2A tracing

The A2A specification 1.0.0 names "tracing, and monitoring" as an enterprise-ready principle and defines no header or field for it ([A2A spec](https://a2a-protocol.org/latest/specification/)). kagent does it at the HTTP layer: the inbound A2A middleware starts an `invoke_agent` server span, and the outbound client interceptor calls `propagation.TraceContext{}.Inject` on the request headers, so `orders-agent` called by `concierge` appears under the caller's trace ([trace.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/core/internal/a2a/trace.go), [client_interceptors.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/core/internal/a2a/client_interceptors.go)). The Go runtime registers TraceContext and Baggage propagators ([tracing.go](https://github.com/kagent-dev/kagent/blob/v0.10.0/go/adk/pkg/telemetry/tracing.go)). A container agent that wants to join must send `traceparent` itself.

## Part 2: evals

### 8. promptfoo

Runtime. Node.js 22.22.0 or newer; `npx promptfoo@latest`, `npm install -g promptfoo`, or `brew install promptfoo` ([installation](https://www.promptfoo.dev/docs/installation/)).

OpenAI-compatible target. Provider `openai:chat:<model>` with `config.apiBaseUrl` including `/v1` and `apiKeyEnvar` ([openai provider](https://www.promptfoo.dev/docs/providers/openai/)). For LiteLLM: `apiBaseUrl: http://litellm.platform-gateway.svc.cluster.local:4000/v1`.

HTTP target. Provider `https` with `url`, `method`, `headers`, `body` containing `{{prompt}}`, `transformResponse` (for example `json.output`), and `sessionParser` for multi-turn attacks ([http provider](https://www.promptfoo.dev/docs/providers/http/)). This fits `/agents/<team>/<name>/chat` through agentgateway.

Assertions. Deterministic: `contains`, `icontains`, `regex`, `is-json` (with optional schema), `javascript`, `python`. Model-graded: `llm-rubric`, `similar`, `factuality`, `model-graded-closedqa` ([assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/)). Set the grader with `defaultTest.options.provider` ([guide](https://www.promptfoo.dev/docs/configuration/guide/)); Ollama works as grader as `ollama:chat:<model>` with `OLLAMA_BASE_URL` ([ollama](https://www.promptfoo.dev/docs/providers/ollama/)).

CI. `promptfoo/promptfoo-action@v1` takes `github-token`, `prompts`, `config`, and optional `openai-api-key`, posts results to the PR, and caches with `actions/cache@v4` ([GitHub Action](https://www.promptfoo.dev/docs/integrations/github-action/)). `promptfoo eval` exits `100` when any test fails or the pass rate is below `PROMPTFOO_PASS_RATE_THRESHOLD`, `1` on other errors ([CLI](https://www.promptfoo.dev/docs/usage/command-line/)). Responses cache at `~/.promptfoo/cache` for 14 days ([caching](https://www.promptfoo.dev/docs/configuration/caching/)).

Red team. `promptfoo redteam run` then `redteam report` ([quickstart](https://www.promptfoo.dev/docs/red-team/quickstart/)). `redteam.provider` sets the attack and grading model, `numTests` defaults to 5 per plugin, `purpose` steers generation. Generation uses promptfoo's remote service by default; `PROMPTFOO_DISABLE_REDTEAM_REMOTE_GENERATION=true` falls back to local generation with lower quality ([configuration](https://www.promptfoo.dev/docs/red-team/configuration/)). Plugins marked with a globe icon use remote inference in the Community edition ([plugins](https://www.promptfoo.dev/docs/red-team/plugins/)). Collections `owasp:llm` and `owasp:llm:01` for prompt injection with `jailbreak` and `jailbreak-templates` strategies ([OWASP LLM](https://www.promptfoo.dev/docs/red-team/owasp-llm-top-10/)); `owasp:agentic` maps ASI01 to `hijacking`, `system-prompt-override`, `indirect-prompt-injection`, ASI02 to `excessive-agency`, `mcp`, `tool-discovery`, ASI03 to `rbac`, `bfla`, `bola` ([OWASP Agentic](https://www.promptfoo.dev/docs/red-team/owasp-agentic-ai/)). `indirect-prompt-injection` takes `indirectInjectionVar` naming the untrusted variable ([plugin](https://www.promptfoo.dev/docs/red-team/plugins/indirect-prompt-injection/)). The agent guide recommends `rbac`, `bola`, `bfla`, `ssrf`, `tool-discovery`, `excessive-agency`, `hijacking`, and `crescendo` ([agents](https://www.promptfoo.dev/docs/red-team/agents/)).

Cost. Each `llm-rubric` assertion is one grader call per test case per run. No primary source states a dollar figure; the cost is the grader model's price times the test count, and caching makes repeat runs free until the prompt or the response changes ([caching](https://www.promptfoo.dev/docs/configuration/caching/)).

### 10. Prompt-injection and agent-safety test sets

garak (NVIDIA). Probes include `promptinject`, `dan`, `encoding`, `donotanswer`; generators include OpenAI, REST endpoints returning text or JSON, and Ollama through `ollama.OllamaGeneratorChat` with default host `127.0.0.1:11434` ([README](https://github.com/NVIDIA/garak/blob/main/README.md), [ollama.py](https://github.com/NVIDIA/garak/blob/main/garak/generators/ollama.py)). ### 11. Where to gate

Today `validate.yml` lints and renders the chart, runs schema negative tests, and runs `unittest` ([validate.yml](../../.github/workflows/validate.yml)). Nothing calls a model. Three places an eval can run:

(a) App build. `build-agent.yml` builds the container image. A promptfoo job there can start the app, point the `https` provider at `localhost:8080`, and set `LLM_BASE_URL` to a model the runner can reach. It needs a LiteLLM key or an OpenAI-compatible endpoint as a secret, and it costs money per PR unless the grader is deterministic.

(b) Nightly in-cluster. A CronJob in `platform-observability` runs `promptfoo eval` with the `https` provider against `http://agentgateway-proxy.agentgateway-system.svc.cluster.local/agents/<team>/<name>/chat`, using `ollama_chat/gemma4:12b` through LiteLLM as grader, and writes JSON output to a PVC or posts it to the LGTM Loki. No CI secret, no runner cost, real routing and policies exercised. Failures do not block a merge.

(c) Prompt agents at PR time. A `kind: prompt` agent's behavior is its system prompt plus the model. `helm template` already renders the Agent CR; a CI step can extract the system prompt from the rendered YAML and run promptfoo with `openai:chat:deep-reason` against LiteLLM (needs a key secret and spends tokens) or skip the model and run only deterministic checks on the prompt text (length, required guardrail sentences, banned phrases).

Evidence. Shopify built Sidekick ground truth from production conversations, calibrated LLM judges against human labels (Cohen's kappa 0.02 to 0.61 against a 0.69 human baseline), and runs a merchant simulator over candidate systems before release ([Shopify](https://shopify.engineering/building-production-ready-agentic-systems)). LinkedIn traces with LangSmith before production and OpenTelemetry in production, then persists traces "into datasets that power offline evaluations, model regression tests, and prompt tuning experiments" ([LinkedIn](https://www.linkedin.com/blog/engineering/generative-ai/the-linkedin-generative-ai-application-tech-stack-extending-to-build-ai-agents)). Anthropic: mirror the real task distribution, automate grading, prefer more questions with automated grading over fewer human-graded ones, and grade with a different model than the one under test ([Anthropic](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)).

### 12. Regression checks

Trace-based scoring. Langfuse judge rules match incoming observations on type, name, metadata, user, session, tags, or version and attach one score per observation per evaluator ([Langfuse judge](https://langfuse.com/docs/evaluation/evaluation-methods/llm-as-a-judge)). Phoenix runs evaluators over exported spans and logs results back to the spans ([Phoenix evals](https://arize.com/docs/phoenix/evaluation/llm-evals)). Both turn "did quality drop this week" into a query.

Datasets from production. Langfuse dataset items take `source_trace_id`, so a bad trace becomes a test case with an expert-written expected output ([datasets](https://langfuse.com/docs/evaluation/experiments/datasets)). LiteLLM spend logs hold the prompt and response only when `store_prompts_in_spend_logs` is on ([cost tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)); that reverses the current `turn_off_message_logging: true` posture and needs a data-retention decision. kagent's audit log stream (section 1) lands in Loki, and Loki queries by agent name can seed a dataset for prompt agents with no LiteLLM change.
